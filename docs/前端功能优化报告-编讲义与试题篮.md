## 一、需求①：把「添加题目」放进二级菜单

### 现状
顶部导航是平铺的 4 个一级项（`src/components/AppShell.tsx` 的 `NAV` 常量）：

```
📋 选题 ｜ ➕ 添加题目 ｜ 🧺 试题篮 ｜ ⚙️ 设置
```

### 建议方案

保留「选题」「试题篮」「编讲义」为**一级菜单**，把低频操作收进二级：

```
📋 选题 ｜ 🧺 试题篮 ｜ 📝 编讲义 ｜ ▾ 更多        ⚙️ 🔄 🌙
                                  ├─ ➕ 添加题目
                                  └─ ⚙️ 设置
```

**实现要点**
- 在 `AppShell.tsx` 增加一个 `Dropdown` 结构：一级渲染「更多」，hover / 点击展开二级列表
- 二级项同样保留**当前页高亮**（`isActive` 逻辑复用）
- 若「添加题目」是当前页，则「更多」按钮本身呈现激活态，避免用户迷失
- 移动端（<720px）沿用现有的「只显示图标」策略，二级菜单改为点击弹出

**收益**：一级导航从 4 项减到 4 项但语义更清晰（高频 vs 低频分离），「添加题目」不再占用宝贵的一级位置，为「编讲义」腾出空间。

**待确认 Q1**：二级菜单里除了「添加题目」，是否也要把「设置」一起收进去？（建议：是，设置同属低频）

## 二、需求②：试题篮瘦身，只做「候选题目清单」

### 现状（问题的根源）

当前 `examBasket/page.tsx` 有 **1011 行**，它其实承担了**两个本应分离的职责**：

1. **试题篮**——展示从选题页勾选过来的题目
2. **组卷 / 讲义**——块编辑器、排版设置、试卷分析、实时预览、Word 导出……

这两件事混在一个页面，导致：
- 用户只想「看看篮子里有什么」，却要面对一整套排版工具，认知负担重
- 页面职责过重，后续迭代互相牵制

另外，试题篮的数据通道目前是**单向且一次性**的：
- `FilterableTable.tsx` 把选中题目序列化成文本，写入 `localStorage['questionBarData']`
- 跳转 `/examBasket`，页面读取后**立即 `removeItem`**（第 284 行）
- 也就是**读完即销毁**，刷新页面篮子就空了

### 建议方案

把试题篮重构为一个**纯清单页**，只做三件事：

| 功能 | 说明 |
| --- | --- |
| **展示** | 当前篮内所有题目（题干摘要 / 来源 / 题号 / 题型 / 难度 / 知识点），可直接展开看全文（复用 `MathText`） |
| **管理** | 逐题移除、清空全部、按题型/难度/来源排序与筛选 |
| **交接** | 把篮内题目「送」给编讲义页（见第三章），或导出为 Markdown |

**关键改造：数据结构持久化**

现在 `questionBarData` 是一坨用 `\n\n==========\n\n` 拼接的文本，读一次就丢。建议改为结构化存储：

```ts
// localStorage key: 'highmath.basket.v1'
interface BasketItem {
  qid: string;
  source: string;
  number: string;
  type: string;
  difficulty: number;
  chapter: string[];
  section: string[];
  knowledge: string[];
  /** 题干纯文本摘要，用于列表速览 */
  preview: string;
}
type Basket = BasketItem[];   // 有序数组 = 用户勾选顺序
```

- `FilterableTable` 的「加入试题篮」改为**追加写入**这个数组（去重、保序），而非覆盖式拼接
- 试题篮页读数组渲染；**移除即从数组删除**，不再「读后销毁」
- 刷新、关掉应用再打开，篮内内容都还在（`localStorage` 持久）
- 提供迁移逻辑：首次运行时若检测到旧的 `questionBarData`，自动解析并升级为新结构

**页面布局建议**
```
┌─────────────────────────────────────────────────┐
│ 试题篮  共 12 题            [清空] [导出] [→ 编讲义] │
├─────────────────────────────────────────────────┤
│ ☐ 2024西城一模 T19  解答题 ★★★  [展开▾] [移除]    │
│   考查：导数的几何意义、函数单调性……                │
│ ☐ 2023海淀期末 T7   单选题 ★★   [展开▾] [移除]    │
│   ……                                             │
└─────────────────────────────────────────────────┘
```

**不做的**：块编辑器、排版设置、试卷分析、Word 导出**全部从本页移走**（迁入「编讲义」，见下）。

**待确认 Q2**：试题篮是否要支持**多个篮子**（如「期中卷」「暑假作业」分开放）？建议 v1 先做单篮，多篮作为后续增强。

## 三、需求③：新增「编讲义」菜单

这是本次最大的新功能。核心诉求是**按模块组织讲义 + 从试题篮手动往指定位置插题**。

### 3.1 讲义模块化模型

讲义不再是一份「题目从头排到尾」的平铺文档，而是由**若干具名模块**顺序组成：

```
讲义 = [ 总标题模块 ] → [ 模块1 ] → [ 模块2 ] → ...
```

每个模块可指定类型：

| 模块类型 | 作用 | 自动行为 |
| --- | --- | --- |
| **总标题** | 讲义大标题 / 副标题 / 信息栏 | 渲染为卷头 |
| **知识点标题** | 章节小标题（如「一、导数的概念」） | 支持自动编号 |
| **知识点讲解** | 概念、公式、定理的正文讲解 | 纯文本块（支持 Markdown + KaTeX） |
| **例题讲解** | 典型例题 + 解析 | 题目块容器，可挂题 |
| **真题练习** | 练习题（可附答案） | 题目块容器，可挂题 |
| **自由文本** | 任意补充说明 | 纯文本块 |
| **分页符** | 强制分页 | 导出时插入分页 |

> 说明：现有 `handout.ts` 的 `Block` 模型已经具备 `heading / group / question / text / pagebreak / answers` 六种块，**扩展性天生够用**。本方案主要是**给这些块加上「模块」的语义外壳与预设**，而不是推翻重来。

**建议的数据结构**（在现有 `Block[]` 之上包一层）：

```ts
type ModuleKind =
  | 'title' | 'knowTitle' | 'knowExplain'
  | 'example' | 'practice' | 'text' | 'pagebreak';

interface HandoutModule {
  id: string;
  kind: ModuleKind;
  /** 模块标题，如「一、导数的概念」 */
  title: string;
  /** 该模块下的内容块（复用现有 Block） */
  blocks: Block[];
  /** 题号策略：连续 / 模块内重排 */
  numbering: 'continuous' | 'restart';
}
```

### 3.2 侧边试题篮面板（核心交互）

页面采用**左侧讲义编辑区 + 右侧试题篮抽屉**布局：

```
┌──────────────────────────────┬───────────────────┐
│ 编讲义                        │  试题篮 (12)  [×]  │
│                              │  ───────────────  │
│ ▸ 总标题  [给讲义起个名字___]  │  ☐ T19 解答题 ★★★ │
│                              │  ☐ T7  单选题 ★★  │
│ ▸ 一、知识点标题 [导数概念_]   │  ☐ T12 填空题 ★★  │
│   ▸ 知识点讲解 [公式……]       │    ……             │
│   ▸ 例题讲解                  │  ───────────────  │
│      [在此插入题目 ▾]  ←──────┼─ [插入选中 2 题]   │
│      · T19 解答题             │  [全部插入]        │
│   ▸ 真题练习                  │                   │
│      · T7  单选题             │                   │
│      [在此插入题目 ▾]         │                   │
└──────────────────────────────┴───────────────────┘
```

**插入题目的两种方式**（都支持）：

1. **精确插入**：每个「例题讲解 / 真题练习」模块底部有「＋ 在此插入题目」按钮 → 打开右侧篮面板 → 勾选若干题 → 点「插入选中」→ 题目按勾选顺序插入到**该模块内**的指定位置
2. **快速插入**：篮面板中直接勾选 + 点模块下拉框选择目标模块 → 一次性投放

**可拖动微调**：插入后仍可拖拽题目在模块内、模块间移动（复用现有 `moveBlock` / 拖拽逻辑）。

### 3.3 复用现有能力（重要：不做重复建设）

| 现有资产 | 在「编讲义」中的复用方式 |
| --- | --- |
| `handout.ts` 的 `Block` 模型 + `buildDocumentMarkdown` | 直接作为模块内容块的渲染引擎 |
| `HandoutSettings` + `DEFAULT_HANDOUT_SETTINGS` | 作为讲义全局设置（题号、知识点模板、答案位置等） |
| `analyzeHandout` | 讲义分析（题量、题型分布、难度分布） |
| `handoutExport.ts` 的 `downloadMarkdownZip` / `exportWord` | 讲义导出 Word / Markdown（Pandoc 管线不变） |
| `PRESETS`（排版预设） | 作为讲义模板预设 |
| `MathText` | 题干 / 讲解内容的富文本渲染 |

> 也就是说：**「编讲义」不是从零写一个新系统，而是把现有 `examBasket` 里那套组卷能力「搬过去 + 加上模块容器 + 加上侧边篮面板」**。工作量主要集中在模块容器与插入交互，底层渲染/导出几乎零改动。

**待确认 Q3**：模块类型清单是否够用？是否还需要「★ 学习目标」「✎ 课堂小结」「📌 易错提醒」这类预设模块？（建议：先做报告中的 7 种，其余按需再加）

**待确认 Q4**：题号在模块之间是**整篇连续**还是**模块内重新计数**？（建议：默认模块内重排，符合「例题 1、2、3 / 练习 1、2、3」的常见讲义习惯，且可开关）

## 四、需求④：讲义草稿自动留档（防丢失）

### 现状
`examBasket` 目前只持久化了**设置**（`highmath.handoutSettings`）和**模板**（`highmath.handoutTemplates`），
**讲义的正文内容完全没有留档** —— 刷新或误关页面，正在编辑的讲义就没了。

### 建议方案：双层留档

**第一层：浏览器本地自动存（即时、无感）**

- `localStorage['highmath.handout.draft.v1']`，存模块树 + 设置 + 光标位置
- **防抖自动保存**：内容变更后 800ms 写入（避免每次按键都写）
- 打开页面时若检测到草稿，提示「发现未完成的讲义，是否恢复？」
- 容量受限（localStorage 约 5MB），需对题干做截断保护；超出时降级到第二层

**第二层：本地草稿文件（大容量、可备份）**

- **桌面版**：通过 Electron 主进程写入 `%APPDATA%\HighMath\drafts\<讲义名>.json`（**应用数据目录，不在题库内**）
- **Web 版**：通过新增的 `/api/drafts` 路由写入服务端工作目录（或 `os.tmpdir()`）
- 每次自动保存时同步写文件；崩溃 / 断电也能恢复

**建议补充能力**
- **草稿列表**：打开「编讲义」时列出历史草稿，可选择继续编辑
- **自动命名**：按「总标题 + 日期时间」命名，如 `导数专题_20261009_1730.json`
- **手动导出/导入**：把草稿导出成 `.json` 文件，换机时能带走

**存储位置一览（关键：都不碰题库）**

| 环境 | 草稿位置 |
| --- | --- |
| 桌面版 | `%APPDATA%\HighMath\drafts\*.json` |
| Web 版 | 服务端 `os.tmpdir()/highmath-drafts/` 或配置的工作目录 |
| 兜底 | 浏览器 `localStorage` |

**待确认 Q5**：草稿保留策略？建议：**保留最近 20 份 + 自动清理超过 30 天的**，避免无限增长。

**待确认 Q6**：Web 版是否需要草稿功能？（桌面版肯定要；Web 版若多人共用服务端，草稿会互相可见，可能需要按用户隔离或干脆只存浏览器）

## 七、一句话总结

- **①** 导航加二级菜单，「添加题目」降级
