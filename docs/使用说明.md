## 一、这是什么

HighMath 是一个**以文件夹为数据库**的高中数学题库工具：

- 每道题是一个 `.md` 文件，放在题库目录里，可被 Obsidian、Git、网盘直接管理；
- 程序负责：**按三级分类筛选**、**录入新题**、**勾选组卷**、**按模块编排讲义并导出**；
- 桌面版（Windows）双击即用，不需要装 Node.js；
- 同一套代码也可部署到 Linux 服务器，做成网页应用。

> **数据永远是普通文件。** 程序只读写这些 `.md` 文件，不引入任何数据库；卸载程序不会影响你的题库。

## 二、桌面版（Windows）

### 2.1 安装

1. 双击 `HighMath-Setup-2.2.0.exe`；
2. 若弹出 SmartScreen 提示（未购买代码签名证书），点「更多信息」→「仍要运行」；
3. 选择安装位置 → 安装 → 桌面出现 HighMath 图标。

> 也提供免安装版 `HighMath-Portable-2.2.0.exe`，双击直接运行。
> （`desktop/dist/` 下为当前版本的 Setup 与 Portable 两个安装包。）

### 2.2 首次启动：设置题库目录

第一次打开会看到自带的示例题库（38 道题）。要换成你自己的题库：

1. 点右上角 **⋯ 更多 → ⚙ 设置**；
2. 在「**1. 题库位置**」点 **浏览…**，选择你的题库文件夹；
3. 选择模式：
   - **Obsidian Vault 模式**（默认）：你选的是 Vault 根目录，题目放在其中的 `题库` 子目录里。
     > 例：选 `D:\高中数学`，程序读取 `D:\高中数学\题库\**\*.md`。
   - **直接题库模式**：你选的目录本身就是题库目录（里面直接是各个来源文件夹）。
4. 点 **校验**，确认显示「✅ 校验通过」及题目数量正确；
5. 点 **保存配置**。

> 校验会报告：题目数量、来源数量、图片目录、知识点总表（含章/节/知识点数量）、目录是否可写。

## 四、选题（首页）

### 4.1 三级分类筛选（章 → 节 → 知识点）

顶部提供三个**级联下拉**，按「章 → 节 → 知识点」自上而下逐级收窄：

| 下拉 | 含义 | 说明 |
| --- | --- | --- |
| **章** | 一级分类，如「三角函数」 | 选中后，「节」只列出该章下的节 |
| **节** | 二级分类，如「三角恒等变换」 | 选中后，「知识点」只列出该节下的知识点 |
| **知识点** | 三级分类，如「【必备知识】两角和与差的正余弦公式」 | 精确到单个考点 |

**联动规则**：
- 选「章」自动清空「节」和「知识点」；选「节」自动清空「知识点」；
- 选项顺序与《知识点总表》一致（即教材顺序），且**只列出题库里实际存在的项**，不会出现「选了没结果」。

### 4.2 其他筛选条件

- **年级 / 来源 / 类别**：下拉选择
- **题号范围 / 难度范围**：区间输入（难度 0~1，越大越容易）
- **标签**：下拉选择
- **qid 列表**：粘贴一批 qid，按输入顺序展示

### 4.3 列表与视图

- 表格视图显示：qid、来源、题号、题型、年级、类别、难度、**章、节**、知识点、标签；
- 点行可展开详情（题干 / 选项 / 答案 / 解析）；
- 右上角可切换 **📖 浏览** 卡片视图，更适合逐题阅读；
- 勾选题目后点 **加入试题篮**（或单题直接加）。

> 程序**不会**自动监听文件变化。在 Obsidian 或外部改了题库后，点 **🔄 刷新题库** 重新扫描。

## 五、试题篮

试题篮是一个**纯粹的候选清单**，只做两件事：看清已选了什么、把题送去编讲义。

| 功能 | 说明 |
| --- | --- |
| **列表** | 显示每题来源、题号、题型、难度、知识点、题干预览 |
| **单题移除** | 点题目右侧 ✕ 移除 |
| **批量移除** | 勾选多题后点「移除选中」 |
| **清空** | 一键清空整个试题篮 |
| **去编讲义** | 把**全部**试题篮题目送去「编讲义」页 |
| **选中后去编讲义** | 只把**勾选的部分**送去「编讲义」页 |

> 试题篮数据存在浏览器本地（`highmath.basket.v1`），刷新页面不会丢失。
> 送题到讲义页通过一次性会话通道传递，到达编讲义页后自动清空该次传递标记，避免重复导入。

## 六、编讲义

「编讲义」是本工具的核心创作页面，用于把散题**按教学结构编排**成一份可直接打印的讲义。
自 v2.2.0 起采用 **PDF 优先**架构：预览即所得，导出 PDF 与预览逐页一致。

### 6.1 页面结构

```
┌─────────────────────────────────────────────┬──────────────────┐
│  讲义模块区（从上到下依次是各个模块）          │   试题篮抽屉      │
│  🏷️ 总标题                                    │  （可展开/收起）  │
│  📌 知识点标题                                 │                  │
│  📖 知识点讲解                                 │  从试题篮挑题，   │
│  💡 例题讲解   ← 可插入题目                    │  插入到指定模块   │
│  🔀 变式训练   ← 可插入题目                    │                  │
│  ✏️ 真题练习   ← 可插入题目                    │                  │
│  🧭 方法总结                                   │                  │
│  💬 提示框                                     │                  │
│  📝 自由文本                                   │                  │
│  ⤵ 分页符                                     │                  │
└─────────────────────────────────────────────┴──────────────────┘
```

### 6.2 十种模块类型

| 图标 | 模块 | 可放题目 | 说明 |
| :---: | --- | :---: | --- |
| 🏷️ | **总标题** | — | 讲义主标题，可加副标题文本 |
| 📌 | **知识点标题** | — | 分节小标题，默认参与自动编号（紫色卡片） |
| 📖 | **知识点讲解** | — | 正文讲解，支持公式（`$...$`）（蓝色卡片） |
| 💡 | **例题讲解** | ✅ | 存放例题，可按题计分（橙色卡片） |
| 🔀 | **变式训练** | ✅ | 例题的变式题，与例题形成一组（青色卡片） |
| ✏️ | **真题练习** | ✅ | 存放练习题，可按题计分（灰色卡片） |
| 🧭 | **方法总结** | — | 方法/技巧归纳（绿色卡片） |
| 💬 | **提示框** | — | 提示 / 易错 / 注解三种语气（红色卡片） |
| 📝 | **自由文本** | — | 任意补充说明 |
| ⤵ | **分页符** | — | 在此处强制分页 |

> 每个模块可单独设置：**是否自动编号**、**是否分页**、**折叠/展开**。
> 例题 / 变式 / 练习模块还支持给每题填**分值**，导出时自动统计总分。
> 提示框模块可切换「提示 / 易错 / 注解」三种语气，标签随之变化。

### 6.3 插入题目的两种方式

**方式 A：从试题篮插入（推荐）**
1. 点右上角展开**试题篮抽屉**；
2. 在某个模块（例题讲解 / 变式训练 / 真题练习）上点「**插入题目**」；
3. 在抽屉里**勾选部分题目**（或全选），点「插入到这里」；
4. 题目按勾选顺序插入该模块的指定位置，可继续手动拖动/排序。

**方式 B：粘贴文本**
- 在模块内直接粘贴一段 markdown（可含多题，用 `==========` 分隔），程序自动拆题登记。

> **关键设计**：题目在讲义里只存 `qid` 引用，题面与解析在编排时**快照进草稿**。
> 因此即使源题库文件后来变动，已编好的讲义仍能正常预览与导出。

### 6.4 A4 分页预览（PDF 优先的核心）

右下预览区不再是「网页流式预览」，而是**真实的 A4 纸张视图**：

- 基于 **Paged.js**（W3C CSS Paged Media 的浏览器实现）实时分页，所见即 A4；
- 顶部状态栏显示 **「共 N 页 · A4」**；
- 支持 **缩放**：`−` / 百分比 / `+` / `100%` 复位；
- 提示语「**导出 PDF 与此预览完全一致**」是**结构性保证**——预览与导出 PDF 用的是
  **同一份 HTML + 同一套 `@page` CSS**，不是两套渲染逻辑。

> 顶部另有**统计分析**：总题数、总分、按题型分布、按难度分布、按知识点分布。

### 6.5 版面与打印设置

右侧设置面板新增分组（**PDF 优先**）：

| 分组 | 选项 | 说明 |
| --- | --- | --- |
| **版面** | 输出模式 | 教师版 / 学生版 / 双版本（见 6.6） |
| | 选项排布 | 每行一个 / 每行两个 / 每行四个 |
| | 正文分栏 | 单栏 / 双栏 |
| | 显示页码 | 开/关，格式自定义（`{page}` `{pages}`） |
| | 页眉 / 页脚 | 自定义文字，打印在每页顶部/底部 |
| | 卡片皮肤 | 是否为各模块套用带底色的卡片样式 |
| **水印** | 水印开关/文字/透明度 | 整页斜向水印，适合标注「学生版」「草稿」等 |
| **学生版留白** | 按题型自动留白 | 单选/多选/填空/解答分别设定留白毫米数 |
| | 统一附加留白 | 在自动留白基础上再加固定高度 |

### 6.6 教师版 / 学生版 / 双版本

- **教师版**：完整显示题目、答案、解析；
- **学生版**：**自动隐藏全部答案与解析**，并按题型在每题下方插入答题留白
  （解答题默认 60mm、填空题 22mm、选择题不留白；可在设置里逐类调整）；
- **双版本**：一次生成两份文件。

个别题目可在题目条目上勾选「学生版留白覆盖」，单独指定该题留白高度。

### 6.7 导出

| 按钮 | 产物 | 说明 |
| :---: | --- | --- |
| 📕 **导出 PDF** | `.pdf` | **主交付物**。桌面版直存文件；网页版走系统打印对话框选「另存为 PDF」 |
| 📄 Word | `.docx` | **补充格式**，便于二次编辑；复杂版面（分栏、卡片、水印）以 PDF 为准 |
| 📋 复制 Markdown | 剪贴板 | 纯文本，便于再加工 |
| 📦 Markdown (.zip) | `.zip` | markdown + 图片一起打包 |

> **为什么以 PDF 为准**：Word 文档模型与网页排版模型不同，分栏、卡片底色、
> 水印等版式在 Word 里难以完全还原。PDF 与预览同源同渲染，因此是精确交付格式；
> Word 仅作可编辑补充。

## 七、添加题目（录入）

两种方式，都在 **⋯ 更多 → ➕ 添加题目** 页面。

### 7.1 方式一：粘贴

把 AI 按《AI 录入规范》整理好的 markdown 粘进左侧输入框，右侧实时预览拆分出的题目。确认无误后点 **确认入库**。

### 7.2 方式二：拖入 .md / .zip（推荐）

1. 把 `.md` 文件（可多选）或 `.zip` 压缩包**直接拖进左侧区域**（也可点「📥 导入 .md / .zip」选择）；
2. 程序先**校验**，弹出报告：

   ```
   ✅ 通过 12 题   ❌ 错误 2 题   ⚠️ 警告 5 题   共 19 题
   ```

   - **错误**：结构性问题（缺 YAML、缺题型、选择题没有 `[选]` 标记……），**不会入库**；
   - **警告**：可疑但可入库（章/节/知识点不在总表中、隶属关系不成立、缺答案/解析……）。

3. 选择：
   - **仅导入通过的（跳过重复）** —— 已存在的文件不动；
   - **导入并覆盖重复** —— 覆盖前自动备份为 `.md.bak`。

> 一个文件里可有多道题，用 `==========`（**固定 10 个等号**）分隔，程序自动拆分。

### 7.3 校验规则

| 级别 | 触发条件 |
| --- | --- |
| ❌ 错误 | 无 `---` YAML；缺 `type` 或题型非法；缺 `## 题目`；选择题无 `[选]`；填空题无 `[填]` |
| ⚠️ 警告 | **章/节/知识点不在总表中**；**节不属于所列章、知识点不属于所列节**；缺 `## 答案` / `## 解析`；缺来源/题号/难度；`[选]`/`[填]` 误入 `$...$` 内；填空题多写了 `## 选项` |

## 八、题库目录结构

**Obsidian Vault 模式**（推荐）：

```
D:\高中数学\                 ← 在设置里选这个目录
├── 题库\                    ← 名字默认「题库」，可在设置里改
│   ├── 25全国1\
│   │   ├── 25全国1-T1.md
│   │   └── 25全国1-T2.md
│   └── 25全国2\
│       └── 25全国2-T1.md
├── images\                  ← 题目用到的图片（sha256 命名）
│   └── a1b2c3....jpg
└── 高中数学知识点总表.md      ← 三级分类与校验的依据
```

**直接题库模式**：设置里选到 `题库` 这一层，并把「题库子目录名」改为 `.`。

> 目录结构与内容**完全由你掌控**，程序不会重排、不会改名。因此 Obsidian 阅读与手动校对**不受任何影响**。

### 单题文件格式

```markdown
---
qid: 1781356597883061
grade: 高三
source: 25全国1
number: T1
type: 单选题
difficulty: 0.94
semester: 高三下学期
exam_type: 高考真题
chapter: [复数]
section: [复数的概念, 复数的四则运算]
knowledge: [【必备知识】复数的概念和分类, 【必备知识】复数的四则运算]
ai_tags: []
tags: []
status: 待入库
selected: false
---

## 题目
$(1 + 5\mathrm{i})\mathrm{i}$ 的虚部为 [选]

## 选项
A．$-1$
B．$0$
C．$1$
D．$6$

## 备注

### 我的备注

### AI备注


## 答案
C

## 解析
因为 $(1+5i)i=i+5i^{2}=-5+i$ ，所以其虚部为 1，故选：C.
```

> **字段顺序照抄，不要增减字段。**
> `chapter` / `section` / `knowledge` **必须各自写在一行内**，用半角逗号 + 空格分隔（如 `[A, B]`）。多行 `- ` 列表在网页端导入模式下会导致字段丢失。

## 九、知识点总表与三级分类（重要）

《知识点总表》是**三级分类的唯一依据**，同时用于**校验录入题目的章/节/知识点**，防止 AI 自造名称污染分类体系。

### 9.1 三级结构

总表按 **「一级（章）→ 二级（节）→ 三级（知识点）」** 组织，对应题库 YAML 的三个字段：

| 层级 | 名称 | YAML 字段 | 总表取值位置 |
| --- | --- | --- | --- |
| 一级 | 章 | `chapter` | 表格「一级（章）」列 |
| 二级 | 节 | `section` | 表格「二级（节）」列 |
| 三级 | 知识点 | `knowledge` | 表格「知识点（knowledge 取值）」列（含【】前缀） |

**三者不是各选各的，而是逐级推导**：先选定 1~4 个三级知识点，再反查它们所属的「节」和「章」，去重后得到 `section` 与 `chapter`。

**包含关系必须成立**：每个 `section` 隶属于所列某个 `chapter`；每个 `knowledge` 隶属于所列某个 `section`。

### 9.2 放置位置

放在题库根目录即可（以下位置程序会自动查找）：

1. `<题库根目录>\高中数学知识点总表.md`
2. `<Vault 根目录>\高中数学知识点总表.md`
3. 设置页里手动指定的路径

### 9.3 表格式样

```markdown
## 第二章　集合与常用逻辑用语

### 集合的基本运算

| 序号 | 一级（章） | 二级（节） | 知识点（knowledge 取值） | 难度 | 特殊标签解读 |
| ---: | --- | --- | --- | :---: | --- |
| 17 | 集合与常用逻辑用语 | 集合的基本运算 | 【必备知识】交集及其常用结论 | ★ | ... |
| 19 | 集合与常用逻辑用语 | 集合的基本运算 | 【必备知识】补集及其常用结论 | ★ | ... |
```

程序读取「一级（章）」「二级（节）」「知识点」三列构建三级索引。若表格没有章/节列，则退化为按 `## 第X章` / `### 节名` 标题层级推导。

> 找不到总表时，程序**跳过**三级校验（不拦截导入），设置页会给出提示。

### 9.4 四类知识点前缀

| 前缀 | 含义 | 何时选用 |
| --- | --- | --- |
| 【必备知识】 | 定义、公式、定理、基本运算等主干知识 | 题目**直接考查**某个概念/公式/定理本身 |
| 【情境问题】 | 具体题型、应用情境、组合与综合问题 | 题目把知识**放进具体情境或组合**里考查 |
| 【能力素养】 | 数学文化、跨模块素养、数学建模等 | 题目涉及文化背景/建模/非常规素养 |
| 【思想方法】 | 数形结合、分类讨论、化归转化等通法 | 题目以某种**思想方法**为核心解法 |

> 前缀是名称的一部分，**必须一并逐字复制**。

## 十、导出讲义

### 10.1 从试题篮导出（快照式）

在试题篮里选中题目 → 直接导出：
- **复制为 Markdown** / **打包下载 Markdown (.zip)**：无需额外依赖，图片一并打包；
- **Word (.docx)**：需要 Pandoc（设置页「4. Word 导出」可检测）。

### 10.2 从编讲义导出（编排式）

在编讲义页按模块编排好后导出，输出包含**总标题、知识点标题、讲解、例题、变式、练习、方法总结、提示框、分页**的完整讲义，自动统计总分。

**四种产物**（详见 6.7）：

| 产物 | 用途 | 精度 |
| --- | --- | :---: |
| **PDF** | 打印、分发、存档 | ⭐ 精确（与 A4 预览逐页一致） |
| Word (.docx) | 需要二次编辑时 | 补充格式 |
| Markdown / .zip | 纯文本再加工 | — |

> **PDF 是主交付物**：预览与 PDF 共用同一份 HTML 与同一套 `@page` CSS，因此「所见即所得」是结构性保证。
> 桌面版点「📕 导出 PDF」直接弹出保存框、后台无头打印，不经过浏览器打印对话框。
>
> Word 导出需 Pandoc（设置页「4. Word 导出」可检测）；未安装时**自动降级**为内置转换。
> 自动探测顺序：设置页填写 → `PANDOC_PATH` 环境变量 → 项目内 `tool/pandoc-3.10/` → 系统 PATH。
> 注意：分栏、卡片底色、水印等版式在 Word 中难以完全还原，这类需求请用 PDF。

## 十一、草稿与自动保存

编讲义时**无需手动保存**——程序会自动把当前讲义存为草稿。

| 项目 | 说明 |
| --- | --- |
| **触发时机** | 编辑后约 0.8 秒自动保存；关闭/刷新页面前再强制保存一次 |
| **保存内容** | 模块结构、设置、**题目快照**、自由文本 |
| **保留数量** | 最近 **20 份**草稿，超过自动清理最旧的 |
| **过期时间** | **30 天**未更新的草稿自动清理 |
| **存放位置** | 桌面版：`%APPDATA%\HighMath\drafts\`（菜单「文件 → 打开草稿文件夹」）<br>网页版：服务器数据目录下的 `drafts/`（通过 `/api/drafts` 接口）<br>兜底：浏览器 `localStorage`（仅保留最近 2 份） |

**为什么草稿要存"题目快照"**：讲义的题目按 `qid` 引用题库。若只存引用，一旦题库变动或换台机器，预览就会「内容加载失败」。因此程序把**被引用的题目原文**一并快照进草稿，保证讲义随时可打开、可预览、可导出。

## 十三、服务器版部署（Linux）

桌面版和服务器版是**同一份代码**，只是启动方式不同。

### 13.1 Docker（推荐）

```bash
# 1. 构建（默认不含 pandoc，体积小）
docker build -t highmath .

# 需要 Word 导出时（镜像会明显变大）
docker build --build-arg INSTALL_PANDOC=1 -t highmath .

# 2. 运行：把题库目录挂载到 /data
docker run -d --name highmath \
  -p 3000:3000 \
  -v /srv/mathbank:/data \
  -e VAULT_PATH=/data \
  -e BANK_DIR_NAME=题库 \
  highmath
```

或使用 `docker-compose.yml`：

```bash
# 修改 compose 里的 volumes 路径后
docker compose up -d
```

浏览器访问 `http://<服务器IP>:3000`。

> 若 `/srv/mathbank` 本身就是题库目录（不是 Vault 根目录），把 `BANK_DIR_NAME` 设为 `.`。

### 13.2 裸机 / systemd

```bash
# 构建
npm ci && npm run build

# 拷贝 standalone 产物到部署目录
mkdir -p /opt/highmath && cp -r .next/standalone/. /opt/highmath/
cp -r .next/static /opt/highmath/.next/static
cp -r public /opt/highmath/public

# 启动
VAULT_PATH=/srv/mathbank PORT=3000 HOSTNAME=0.0.0.0 node /opt/highmath/server.js
```

systemd 单元（`/etc/systemd/system/highmath.service`）：

```ini
[Unit]
Description=HighMath
After=network.target

[Service]
WorkingDirectory=/opt/highmath
Environment=VAULT_PATH=/srv/mathbank
Environment=PORT=3000
Environment=HOSTNAME=0.0.0.0
ExecStart=/usr/bin/node /opt/highmath/server.js
Restart=always

[Install]
WantedBy=multi-user.target
```

### 13.3 服务器端使用差异

- **没有**「浏览…」原生选目录按钮 —— 在设置页**输入路径**后点校验；
- 配置可用**环境变量**注入，无需改配置文件；
- 题库目录需给运行用户**写权限**（录入题目要写文件）；
- 草稿写入服务器数据目录的 `drafts/`（`/api/drafts` 接口）。

## 十五、常见问题

**Q：双击后白屏 / 一直转圈？**
A：服务启动需要几秒。若超过 30 秒仍白屏，请重启应用；若仍不行，查看启动日志：
`%APPDATA%\HighMath\desktop.log`（也可用菜单「文件 → 打开日志文件」）。日志记录端口选择、服务启动、窗口加载的每一步。

**Q：编讲义预览显示「内容加载失败」？**
A：这通常意味着该题的题面没能快照进草稿。**正常情况下程序会自动快照**；若偶发，请确认题目已完整入库，然后重新从试题篮插入一次。

**Q：编讲义页面滚动不了？**
A：v2.2.0 已改为**整页自然滚动**，试题篮抽屉在页面内独立滚动。若仍异常，请升级到 2.2.0。

**Q：讲义草稿存在哪里？会不会丢？**
A：桌面版存在 `%APPDATA%\HighMath\drafts\`（菜单「文件 → 打开草稿文件夹」可直接打开）。程序每约 0.8 秒自动保存，并保留最近 20 份、30 天内的草稿。

**Q：导出的 PDF 和预览不一致 / 公式、图片丢了？**
A：PDF 与预览共用同一份 HTML，理论上一一对应。若发现公式或图片缺失：
① 确认题库里的图片是本地文件（`images/` 子目录），网络图片可能因离线而加载失败；
② 网页版调用的是系统打印对话框，请选择「**另存为 PDF**」并**关闭「页眉页脚」**选项（否则浏览器会额外加一行 URL 页脚）；
③ 桌面版是无头打印，不受上述影响，推荐用桌面版导出。

**Q：预览显示「暂无内容」或分页脚本加载失败？**
A：A4 预览依赖 `public/paged.polyfill.js`。若该文件缺失或未随构建打包，预览会退化。
请确认 `public/` 下存在 `paged.polyfill.js` 与 `katex/` 目录（源码构建时须保留）。

**Q：导出 PDF 时弹出的是打印对话框？**
A：说明当前运行在**网页版**（浏览器里），网页无权直接写文件，只能走打印对话框另存。
桌面版（.exe）则有保存框直存，无需经过打印界面。

**Q：在虚拟机 / 远程桌面里打不开？**
A：应用默认**关闭了硬件加速**（文档型界面不需要 GPU），因此兼容虚拟机、远程桌面与无独显环境。如需开启，设 `MATHATLAS_ENABLE_GPU=1` 后重启。

**Q：exe 图标是默认的 Electron 图标？**
A：是的。打包时跳过了 exe 资源编辑（原因见第十六节），**安装包与桌面快捷方式仍使用 HighMath 图标**，功能不受影响。

**Q：「章 / 节」下拉里没有我要的项？**
A：下拉选项只显示**题库里实际存在**的分类。说明还没有题目填过该章/节——需在录入时正确填写 `chapter` / `section`。

**Q：筛选「章」之后结果为空？**
A：说明题库里的题目还没填 `chapter` 字段（旧题可能只有 `knowledge`）。可先按「知识点」筛，或把旧题补上章/节。

**Q：提示「未找到题库目录」？**
A：到设置页重新选题库目录并点「校验」。注意 Obsidian Vault 模式要选 **Vault 根目录**（包含 `题库` 子目录的那一层）。

**Q：图片不显示？**
A：图片需放在 `images` 目录。设置页会显示实际解析到的图片目录；若显示「不存在」，上传新图片时会自动创建。

**Q：我在 Obsidian 里改了题目，程序没更新？**
A：点首页「🔄 刷新题库」。

**Q：导入时提示「疑似自造知识点」或「隶属关系不成立」？**
A：说明知识点（或章、节）不在《知识点总表》里，或层级对不上。请回到总表逐字复制标准名称。报告里若给出「按知识点反推，chapter/section 还应包含：……」，可据此修正。

**Q：Word 导出失败？**
A：设置页「4. Word 导出」点「检测」。不可用时请安装 Pandoc，或填写 pandoc 路径。Markdown 导出不需要 Pandoc。

**Q：会不会把我的题库搞乱？**
A：程序对题库只做两件事：**读** `.md` 文件、**新增**入库的 `.md` 文件（含图片）。**不会移动、重命名或删除任何已有文件**；覆盖同名文件前先备份为 `.md.bak`。
组卷、编讲义、导出等全部功能**只读**题库，不产生任何写入。

## 十六、从源码构建

```bash
# 环境要求：Node.js 20+（推荐 22）

# 1. 安装依赖（已配置国内镜像 .npmrc）
npm install

# 2. 开发模式
npm run dev            # http://localhost:3000

# 3. 构建 Web 产物
npm run build          # 产出 .next/standalone
npm run serve          # 直接跑 standalone 服务

# 4. 桌面版
npm run desktop:build  # = build + 装配资源到 desktop/resources/app
npm run desktop:dev    # 装配后用 Electron 启动
npm run desktop:dist   # 打包 Windows 安装包（输出 desktop/dist）
npm run desktop:dist:linux  # 打包 Linux AppImage / deb
```

```
│   │   └── api/              接口（config / knowledge / import / drafts / export-docx …）

│   │   ├── validate.ts       题目校验
```

### 构建注意事项

1. **Electron 二进制体积较大（约 115MB）**，首次安装 `desktop` 依赖时会下载。网络受限时可在 `desktop/.npmrc` 中用 `electron_mirror` 指定镜像。
2. **`desktop/resources/` 必须在 `next build` 之前清空**。它是上一轮构建产生的完整应用副本（含 node_modules）；若留在项目里，Next 会把它当项目文件一起扫描，构建会从几十秒劣化到数分钟甚至卡住。`npm run desktop:build` 已内置 `desktop:clean` 自动处理；**手动分步执行时请务必先跑 `npm run desktop:clean`**。
   同理，不要把 Electron 缓存等大体积目录放进项目内（`next.config.ts` 已排除 `desktop/**`、`.cache/**`）。
3. **`next.config.ts` 的 `outputFileTracingExcludes` 不能排除 `**/*.md`** —— 示例题库 `demo-vault` 本身就是 markdown，排除后 standalone 产物会缺示例题。
4. **Windows 上打包若报「无法创建符号链接」**：这是 `electron-builder` 下载 `winCodeSign` 时，其中的 macOS dylib 符号链接需要管理员权限。本项目已在 `desktop/electron-builder.yml` 中设 `signAndEditExecutable: false` 规避（代价是 exe 内嵌图标为 Electron 默认图标）。若要恢复 exe 图标，可开启 Windows「开发者模式」或以管理员权限构建，然后删掉该项配置。
5. **standalone 产物不含 `.next/static` 与 `public`**，`scripts/prepare-desktop.mjs` 已自动补齐。
6. **构建中断可能残留 `.next/lock`**，导致下次构建静默等待 —— 删掉 `.next` 目录重试即可。
